# AI and measurement method

## Status of the evidence

There is no experimental dataset yet. Everything classified today uses simulated data with demonstration thresholds. Hardware data receives the indicator, anomaly detection and explanation, but **no severity class and no confidence score** until one of these exists:

- a protocol with `validation_status = validated`, thresholds, and a reference to its validation record; or
- a model whose `training_origin` is `experimental`.

## Measurement protocol

Set per station, edited in AI Analysis by an administrator. Saving creates a new version; stored assessments keep the version they used.

**Activity source.** `direct`: the device reports an activity value. `do_uptake_rate`: least-squares decline of dissolved oxygen per hour over the window, meaningful only if the chamber is closed to aeration during that window. Which one is right depends on the final hardware; the software does not decide.

**Inhibition indicator.** `A` is the median activity over the assessment window (default 60 minutes).

| Formula | Expression |
|---|---|
| `percent_difference` | `I = 100 × (A_ref − A_exp) / A_ref` |
| `baseline_normalised` | `I = 100 × (1 − (A_exp / B_exp) / (A_ref / B_ref))`, where `B` is each chamber's baseline median |

Negative values (stimulation) are reported, not clipped. No value is produced when reference activity is at or below `min_reference_activity`.

**Thresholds.** No defaults. The demo protocol's 10, 25 and 50% exist to exercise the software.

## Pipeline

`backend/app/analysis/pipeline.py`, on a 10-minute grid of valid readings.

1. **Sufficiency.** At least half of the paired readings in the window must be valid, otherwise *Not enough data*.
2. **Baseline.** Previous 7 days excluding the latest 6 hours, at least 24 hours of data.
3. **Reference check.** If reference activity itself leaves its baseline (6 robust SD and 8%), the result is *Inconclusive*: a difference between chambers cannot be attributed to the sample.
4. **Anomaly detection.** Robust z-score (median, MAD) of the log activity ratio, flagged beyond 4. One-sided CUSUM on hourly means over 24 hours catches slow drift. These compare the station with itself and need no thresholds.
5. **Classification.** Protocol thresholds if usable, else an eligible model, else *Unclassified*. When both apply, agreement or disagreement is shown.
6. **Confidence.** The calibrated model probability of the assigned class. Absent if no calibrated model applies.
7. **Contributing factors.** For pH, temperature, conductivity, dissolved oxygen and flow: deviation from the sensor's own baseline, lead time against the response onset, and Spearman correlation over 0 to 180 minutes of lag with its effective sample size. One event contains few independent points, so this is presented as association only. Logged events in the preceding 12 hours are listed.
8. **Explanation.** Built from the computed values by fixed rules. No text is generated by a language model, so no statement can appear that the measurements do not support.

Historical patterns (daily severity, time of day, recurring factors, similar events) come from stored assessments and alerts.

## Detection delay

Assessments run on every reading, but each uses the median of the assessment window, so a step change is reported after roughly half the window (30 minutes by default) plus one confirming assessment before an alert opens. A severe result alerts at once. The onset shown to the operator is dated from unsmoothed readings and does not carry this delay. The window is a protocol setting.

## Classifier

A small neural network (7 inputs, 16 hidden units, 4 classes) trained with MindSpore. Features are in `analysis/features.py` and shared by training and inference. Artifact: plain JSON weights, run with numpy locally and in the ModelArts container, with a test that both give identical output.

Current artifact `sim-20261122-9c6107`, MindSpore 2.11.0, 8,838 samples from 150 simulated stations, split by station:

| Held-out simulated stations | |
|---|---|
| Accuracy | 96.2% |
| Macro F1 | 0.962 |
| Errors between neighbouring classes only | 100% |
| Expected calibration error | 0.6% |

**These figures measure agreement with the simulator. They say nothing about real microorganisms or wastewater.** The simulator's dynamics are invented to exercise the software.

Rebuild:

```sh
backend/.venv/bin/python ml/dataset.py --out ml/data/simulated.csv
python3.12 -m venv ml/.venv && ml/.venv/bin/pip install -r ml/requirements.txt
ml/.venv/bin/python ml/train.py --data ml/data/simulated.csv --out ml/artifacts
```

The trainer refuses to mix origins in one dataset.

## Moving to experimental data

1. Run dose-response experiments on the actual device with reference toxicants and real wastewater, recording lab results.
2. Export measurements (raw archives in OBS) and build a CSV with the columns of `ml/data/simulated.csv`, `origin=experimental`, and labels from the **reference method**, not from the indicator. Set `group` to the experiment or culture batch so splits do not leak.
3. Train and review the confusion matrix and calibration. Confidence is hidden automatically if calibration error exceeds 5%.
4. Set thresholds in the protocol with a reference to the validation record and mark it validated.

Open questions for the biology team: which activity measurement the sensors support, chamber aeration and sealing, culture replacement interval, temperature control limits, and the minimum reference activity for a valid comparison.
